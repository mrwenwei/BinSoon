# 清潔隊機車／汽車道路指引

## 正式 API 入口（#11，2026-10-19）

正式首頁的 `#staff/route` 已串接 `/staff/route-stops`，需獨立的隊員 session。起點座標、站點順序、工單 UUID 與 general／recycling 種類集合均直接讀後端；同桶合站但每張工單分別進入詳情。可選全部／一般／回收篩選，不以市民 `is_usable` 過濾清運站點。待修繕、待感測、已結案、撤除／未設置的排除由後端決定，前端不重排。

前景每 10 秒重讀站點，背景停止、離頁取消；亦可手動更新。相同站點／工單只改 generated_at 時保留道路結果；桶位、順序、起點、工單集合或車種變動立即失效並取消舊請求。重讀失敗保留標為可能過期的站點及工單連結，停用道路計算並移除舊指引；成功重讀後仍須手動規劃。401 清除個人站點並連回原路線入口登入，403 不展示其他角色的工單。車種僅在本頁工作階段保留。

沿用現有 Valhalla 車種設定、polyline6 解碼、里程、預估時間與逐段指引。只有公開起點與有序桶位送往道路服務，不附 session、工單 ID、照片或說明；固定示範起點並無隊員 GPS，無即時交通或順序最佳化。公開服務 URL、來源署名、20 秒逾時及 1.5 秒按鈕冷卻沿用下方設定。這個 API 流程不讀舊 localStorage 帳本；下方較早的展示操作與驗證數字屬歷史紀錄。


2026-10-19，使用者要求 P20「今日示範清運路線」依清潔隊員的機車／汽車交通方式給予路線指引。本文件更新 [D flow](D_FLOW.md) 原本只畫站點折線的範圍；不修改市民步行導航、後端或原始資料。

## 操作與行為

在 `#staff/route` 選「機車（一般機車）」或「汽車」，點「產生路線指引」。交通方式在本次工作台頁面切換間保留，重新整理則回到預設機車。只在按鈕操作時請求，沒有進頁自動查詢、定時輪詢或背景重試。

起點沿用大安森林公園展示座標，不讀取隊員 GPS。待辦依現有派工優先度排列，同桶合站、各張工單分開完成；已完成、待修繕、待感測與撤除桶的篩選沿用 D。路線計算依原順序訪站，沒有做最佳化或收運排程。

成功後地圖以實線顯示道路幾何，列全程道路里程與預估行駛時間，每站可展開轉彎指引、道路名及各段距離。常見指令以繁體中文呈現，其他指令保留服務原文。這是靜態道路指引，沒有即時定位追蹤、語音導航、動態交通或作業停靠估時；仍須依現場標誌與車種限制行駛。

車種或站點變動立即清除舊幾何／估時，取消舊請求。延遲抵達的前一車種回應不能覆蓋目前選擇。服務失敗、逾時、限流、缺少站點或錯車種資料皆顯示錯誤，保留站點／工單操作，不畫直線替代道路導航。按鈕有 1.5 秒冷卻，請求逾時 20 秒。

## 服務與資料契約

使用 [Valhalla 路線 API](https://valhalla.github.io/valhalla/api/route/api-reference/)，預設為 [FOSSGIS 公開展示服務](https://valhalla.github.io/valhalla/start/introduction/)。道路資料為 OpenStreetMap，畫面保留底圖署名並提供 Valhalla／FOSSGIS 來源。

- 機車使用 `motor_scooter`（一般機車／速克達），`top_speed=60`、`exclude_highways=true`、`exclude_ferries=true`；這是路徑成本設定，不是道路速限或各地法規保證，也不是大型重機設定。
- 汽車使用 `auto`、`exclude_ferries=true`。不以汽車模型加上機車名稱冒充不同車種。
- 一次 `POST /route` 傳送公開起點及有序桶位，locations 使用 numeric `lat/lon`、`type=break`，回應每段為一站。無帳號、電話、照片、工單說明或 GPS 外傳。
- 要求公里單位，將 response 的 length 轉成公尺、time 以秒讀取；每段 shape 依 JSON response 的 polyline6 解碼為 Leaflet `[latitude, longitude]`。驗證成功狀態、段數、車種、有限非負距離／時間與座標範圍。
- 官方目前沒有繁體中文 narration；以官方 maneuver type 對照繁體中文，保留道路名稱。未知類型保留原指令，避免猜測轉向。

可在 `frontend/.env` 設定 `VITE_VALHALLA_URL` 為相容的完整 `/route` 網址，參考 `frontend/.env.example`，重新啟動 dev／重新 build 後生效。未設定可直接使用；Vite 變數會進入瀏覽器，僅存公開 URL，不存憑證。端點須提供 JSON route 回應，並允許來源網域的 POST、Content-Type 與 X-Client-Id 標頭。

公開展示服務受 fair usage／限流約束，無正式服務保證；不供批次計算或持續追蹤。依 [維運說明](https://github.com/valhalla/valhalla#demo-server)，對外發佈應聯絡服務維運者並保留識別標頭；本次未對外發佈。正式產品應評估相容的自架或有服務承諾的端點，無需改動頁面與工單邏輯。本次未新建付費資源、部署服務或修改現有後端 API。

## 介面優化（2026-10-19）

依使用者指定的 `emil-design-eng` skill 調整 P20，保留路線請求、車種成本、站點順序與工單規則。桌面採地圖與站點並排、地圖隨捲動保留；手機改垂直排列，維持完整地圖署名。

| Before | After | Why |
| --- | --- | --- |
| 大面積表單佔滿整列，地圖與站點上下分離 | 緊湊工具列、道路摘要、地圖與站點並排 | 讓隊員同時掌握位置與下一站。 |
| 車種為一般表單選項 | 圖示雙選切換，整塊可點擊，保留原生 radio 與方向鍵 | 提高辨識度與觸控／鍵盤可用性。 |
| 載入與成功結果出現時推動地圖 | 固定狀態區與里程／時間摘要，尚未計算以破折號顯示 | 等待時版面穩定，不捏造預估數值。 |
| 站點與轉彎指引成為單一長清單 | 編號時間線、下一站標記、可按需展開指引及獨立工單入口 | 降低閱讀與操作負擔。 |
| 缺少按壓回饋、路線頁選單未標示目前頁面 | 指標按壓回饋 140ms、明確 active／focus 狀態、目前頁面標記 | 讓操作立即得到回應。 |

這是工作中反覆使用的頁面，車種切換、鍵盤操作與展開指引皆直接切換，不加進場或排列動畫。按鈕只對指標按壓提供 `transform` 回饋，使用 skill 提供的 `cubic-bezier(.23,1,.32,1)`；等待圖示以 transform 線性旋轉，減少動態效果時停止旋轉並保留文字狀態。桌面 hover 樣式限精細指標裝置，未加入動畫套件。次要文字已提高對比。

新增公開瀏覽器操作回歸：方向鍵切換車種、Enter 展開／收合指引，並在減少動態效果設定下確認載入與成功時地圖位置不跳動。真實路線另檢視 1440px 桌面與 320px 手機，無水平溢出；手機及現場行駛仍未以實機驗證。`typecheck`、`data:check`、`build` 與 Prettier 檢查通過；全套 `test:e2e` 86 項通過（2.6 分鐘）。
