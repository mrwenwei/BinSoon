# B／C flow（2026-10-21）

追加 BinU 修正：前端統一命名 BinU。V1 的 API 建議點在本機帳本加入支持 5–34／反對 1–7 的穩定基礎票（依 Bin ID 固定），以一次性名單避免重複補票；個人票仍可累加、換票或撤票。V2 隱藏建立提案／我的提案，其他頁原深連結仍可達。固定歷史回報由阿順、阿安、阿清處理，僅提供阿順展示登入，新完成案件仍歸登入處理人員；調整展示基準以保持示範總件數，讚仍跟隨該次完成的清潔員。

依更新後的 UI flow 完成 V1–V2、U1–U4、S1–S4，沿用 [M flow](M_FLOW.md) 與既有設計 token。L1 外部通知、G1 新登入／綁定不在本輪範圍；保留原一鍵展示身份登入。

## 市民 B

- V1 `#vote` 為獨立建議點地圖，合併同一 Bin ID 的地圖建議點與提案；未在地圖列表的市民提案依原提案座標呈現，保留來源、不製造既有桶。標記顯示支持票數，面板沿用支持／反對／撤票、關票與完成頁。
- V2 `#vote/votes` 顯示個人投票與四階段進度（建議點、投票、評估會勘、設置）。維持既有 60 人參與及支持率規則，不採參考稿中的示意 7 票。不將票數或階段當作真實設桶。
- U1 `#member` 本機市民首頁為「我的」：可用／審核中點數、兌換、我的 BinU、回報及投票紀錄。原等級與徽章保留於 `#levels`，點數歷史／兌換紀錄／通知保持可達。正式後端會員頁不改為本機頁。
- U2 `#rewards` 市民本機畫面主打試營運 3 點咖啡展示券，其他新獎勵標點數待定。兌換仍沿用原本機原子鎖、指令重試、庫存與點數再次檢查，歷史兌換扣點不重算，無 LINE 或真實核銷。原後端獎品維持後端數值。
- U3 `#reports` 按案件顯示桶名、種類、問題、查證與工作進度及點數。查證屬實且已完成的事件可感謝「該次處理清潔員」，每次完成只可一次，不是對桶按讚。讚隨同一瀏覽器的頁籤及重整保留，S4 依完成清潔員與完成月份顯示，讚不改變件數排名。近期三次不實暫停展示回報七天，其他會員功能不受影響。
- U4 `#adopt` 顯示有效認養各自私人名稱、雙槽狀態、本月回報與完成處理紀錄、滿桶通知偏好及管理入口。每張卡的回報鍵直接走同一個 M4 `#report/<bin_id>?waste_type=...`，由送出時有效認養判斷加倍，沒有另一套快捷表單。原管理及歷史在 `#adopt?manage=1`，私人命名與五個上限維持。

## 清潔員 C

清潔員主分頁為工單／路線／榮譽榜，手機底部、桌面頂部。清潔員登入仍只建立本機模擬身份，沒有後端 staff 權限。

- S1 `#crew` 以待處理／處理中／已完成及即刻處理／一般／讀值異常分組。除了原示範派工，加入市民本機回報事件的展示工單，保留 bin_id 與 waste_type。
- S2 `#crew/task/<id>` 維持手機到場、查證屬實／不實、垃圾組成、模擬完成照的完成條件。市民案件的查證透過同一市民帳本原子鎖結算首報 +1／有效認養首報 +2，一次入帳；查證與完工分開。完工保留完成清潔員、時間、照片及事件關聯，完成頁提供下一單及進度入口。未用相機、GPS、真實派工或 IoT。
- S3 `#crew/route` 共用既有 `CrewRoutePlanner` 的 Leaflet／Valhalla 道路地圖、固定大安森林公園起點、機車／汽車及失敗重試。只規劃未完成且讀值正常的站點，站點變動會使舊指引失效。下方新增已完成／總桶數進度條及已完成桶清單；同桶多張工單都完成才算一個完成桶，異常桶不列路線。初始虛構代號站點明示 local_demo，非 CSV 桶位置；實際 Bin 回報沿用原 ID、座標及來源。
- S4 `#crew/ranking` 顯示月份、行政區、件數排名與市民給各清潔員的讚。排除讀值異常及不實的示範完成。前三名加給只作標示，不計算或支付款項；基準件數與讚明示為 2026-10 展示資料，新增案件與讚按實際展示完成月份歸屬。

本機市民與本機清潔員現在以回報事件、完成清潔員及讚關聯，取代先前完全獨立的展示。正式後端與雲端資料不受影響。滿桶示範完成只將對應種類投影為清空，不影響另一種類；非滿桶完工不清零，不新增或複製歷史。原照片、點數、認養、票與兌換紀錄保留。

驗證在 B／C 實作完成後與 M flow 一起執行；不使用正式資料庫。
