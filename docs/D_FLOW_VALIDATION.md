# D flow 實作與驗證紀錄

2026-10-19。依使用者確認的 [D flow 規格](D_FLOW.md) 完成前端本機展示，以及 A／B 接合；後端、資料庫、原始 CSV 和位置快照未變更。歷史 A／B 驗證紀錄保留，D 接合後以本次紀錄為準。

## 實作範圍

- 同一前端新增 `#staff/tasks` 專用清潔隊介面，採獨立示範身份及導覽；提供派工、詳情、通知、路線及個人榮譽榜，市民榮譽榜僅顯示隊成果。
- `data/workOrders.ts` 集中事件、工單、逐筆查證、清空觀測與績效規則。A 一般回報與 B 快捷通報共用同桶同問題的開放事件，正式查證只結算一次；結案後可建立新事件。虛構市民資料不影響本機會員帳本。
- 接單、到場、逐筆查證、完成照、待感測確認、待修繕及無需處理皆有狀態限制。滿桶採新清空回傳＋查證＋照片提交齊備後自動完成；其他問題不因清空而結案。
- `binDemo` 共用作業覆層套用地圖、清單、篩選、詳情及導航；清空先更新容量，維修／移除限制仍優先。B 的既有桶距離仍按存在性計算。
- 同源帳本透過 Web Locks 在寫入時重讀最新資料，storage 事件更新其他分頁；B 通知設定只合併本次修改欄位。回報、兌換、投票及認養等儲存成功後才顯示成功結果。
- A v2 只讀遷移到 `binsoon-demo-1019-v3`，B 帳本繼續使用既有 key；來源保持原樣。舊點數／資格／兌換延續，不補造清運照片或績效，歷史讚不配給新工單。無法驗證帳本時保留來源並提示。
- 排名按台北曆月完成工作件數，同分並列；歷史基數與新完成增量分開。每次有證據的清運／清潔可按讚一次，讚不發點、不影響名次。前三名專案加給只有展示資格，沒有真實金額或發放。

## 程式審查

比較基準為實作開始的 `17cb8ff9e0568f856110ac0c14524aec8b9535df`，兩位 reviewer 分別檢查 Standards 與 Spec。

### Standards

未發現硬性規範違反或新增的基準設計異味。另建議 B 的異步寫入須等候成功後再回報成功；已修正並加入原流程回歸，覆核無剩餘 Standards 問題。

### Spec

初審發現三項，均已修正，覆核未發現剩餘阻擋項：

1. 提交交易重新讀取 B 帳本，重驗認養、快捷通報資格及撤除狀態；已以 stale adoption 測試先確認失敗，再修正通過。
2. 清運時間僅顯示有證據的完成紀錄，移除每個桶固定的「3 小時前清運」示意文字。
3. 當次感謝數依該次 `cleanup.id` 顯示，避免其他工單的讚混入。

另外，domain 回歸測試發現維修狀態曾把有效 0% 讀值隱藏成未知容量；已將明確容量與不可用限制分開保存，仍維持維修桶不可用。視覺檢查亦修正路線清單雙重編號及地圖提示的定位容器，均經 Spec 窄幅覆核。

## 資料限制與未驗證範圍

這是本機展示，不提供正式身份授權。大安區以外回報仍可沿用 A 展示，但不派給本次大安區隊員。示範照片、定位、通知及固定起點路線皆非現場資料，路線沒有道路可通行性或最佳化保證；原始公布桶日期與現況未經現勘。

正式產品預計由桶頂測距 IoT 經後台更新 App；本次僅有明示的單次示範清空按鈕，未實作裝置接收、校正、離線重試、服務端即時通道或連續感測器模擬。清空不代表桶旁已清理。

未串接真實後端 API、LINE、GPS、相機、簡訊、身份供應商、獎金或實際券商；未進行 Cloud Run 部署、實體手機或真實硬體測試。未改動後端，因此未執行 PostGIS／Docker 測試。底圖依賴外部 OpenFreeMap／WebGL，測試期間可見既有樣式／圖示警告；清單與表單仍提供替代操作。

同源分頁同步不等於跨裝置；需支援 Web Locks 的 HTTPS／localhost 瀏覽器。帳本為單一示範市民與隊員，不模擬多個真實帳號。瀏覽器清除 localStorage 會移除本機展示進度。
