# 提案投票：手動驗收路徑

入口：[要桶投票](http://127.0.0.1:5173/#vote)。手機可使用頂部分頁或左上選單。2026-10-20 唯讀檢查時，Cloud Run 的大安區提案列表為 0 筆，空列表是當時的真實資料，不是按鈕遺失。以下為目前 API 介面，與舊本機展示的「展示控制」不同。

目前本機預覽沿用 Cloud Run API；「送出提案」及投票會留下後端資料。若只查看介面，可先操作到「查詢周邊位置」，不用送出。本文沒有提供真實密碼，也沒有替使用者建立案件或投票。

## 1. 建立提案

1. 開 `#vote`，點「建立提案」。未登入會先要求市民登入，使用 `demo-citizen` 與維運提供的密碼；成功後應返回原頁。
2. 填「提案名稱」「需求原因」。在地圖點選／拖曳選點，或輸入大安區內的經緯度；例如大安森林公園附近 `緯度 25.033`、`經度 121.5358` 可用來查看周邊。實際行政邊界仍由後端判定。
3. 按「查詢周邊位置」。應出現 300 公尺內已設置桶、全市最近桶與附近提案；150 公尺內已有桶是提醒，並非禁止提案。改座標後需重新查詢。
4. 送出前檢查本月剩餘額度，每個市民台北曆月最多 3 筆成功建立。按「送出提案」後，應出現「提案已建立」、剩餘額度及「已包含你的一張支持票」。此時仍是待現勘點，並未真的設桶。
5. 若回應 50 公尺內已有提案，先看附近既有提案；只有不同需求才按「確認是不同需求並建立提案」。區外／額度用完時應顯示原因並保留表單。

## 2. 驗證支持、改票與撤票

1. 成功頁按「查看提案與投票」，或從 `#vote/mine`／全部列表進入詳情。
2. 新提案自帶建立者的支持票，所以自己的「支持」按鈕已選取且不能重複加票。點「反對」應將自己的支持改成反對，總投票人數維持 1。
3. 點「撤票」，自己的票應變「尚未投票」；若沒有其他投票者，總人數變 0、支持率為「無資料」。再點「支持」，應恢復自己的 1 票。
4. 查看 `#vote/votes`「我的投票」與 `#vote/mine`「我的提案」，確認同一提案及自己的票與詳情一致。重新登入也應讀到後端保存的結果。
5. 訪客只能看資料，應看到「登入參與投票」；隊員／管理員身份不應直接代替市民投票。

## 3. 關票、管理員審查與命名

一個帳號不能把自己反覆點成 60 人。未滿 60 人維持「收集中」；至少 60 人且支持率至少 60% 才進「評估中」，支持率不足則進「里辦評議」。關票後不再接受改票或撤票，投票通過也不代表已設桶。

需要這些階段的測試資料時，使用本機 API 攔截測試，勿為驗收向雲端灌票。具有合法階段的本機測試案件，可另開管理員分頁 `#admin/proposals`：里辦評議 → 通過里辦評議 → 評估；評估 →「通過評估」→ 現勘；現勘通過 → 示範設置。拒絕須原因，動作先預覽確認；舊版本被拒絕後應重讀並要求再次確認。

示範設置後，原提案人在詳情填桶名、按「送出命名申請」，管理員「核准桶名」或填原因「退回命名」。核准前公開桶名維持原狀；命名不會改認養者公開名稱。

## 本機自動驗證

於 `frontend/` 執行：

```sh
npx playwright test tests/api-proposals.spec.ts tests/api-governance.spec.ts --workers=1
```

測試用 HTTP 攔截提供成功、鄰近提案、額度／區界、60 人關票、角色／版本與命名資料，不會向 Cloud Run 建提案、投票或部署。這些驗證不能替代真實多使用者的雲端整合驗收。
