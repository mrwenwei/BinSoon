# 清潔隊工單的模擬輸入工具

2026-10-20，依使用者要求，正式 API 清潔隊工單也提供一鍵填入測試資料，與市民回報共用 DEMO PNG 產生器。

## 行為

- 接單、到場維持原按鈕。逐筆查證可預填屬實／不實及明示測試原因，仍須手動確認查證。預填不發 API 請求、不更改點數或工單。
- 完成照片及現況照片分別產生 `demo-completion.png`／`demo-site.png`，圖片明示 DEMO／非現場照片及用途。透過既有照片驗證、媒體上傳、evidence 掛照；原用途、工單、隊員身份與垃圾種類不變。
- 照片草稿中的模擬標記保留於記憶體及預覽，送後端的 PNG 帶浮水印；未增加後端 demo schema。屬實查證的 reason 雖可送入原 API，但後端目前僅為不實保存 rejection_reason，不把屬實說明誤稱為已保存的 demo 證據。
- 待修繕／無需處理原因可預填 `[模擬測試]` 文字。預填不等於修繕或結案，現況照片、全部查證、完成照及滿桶清空條件仍由後端判斷。
- 工單原限制沿用：未到場及非本人不提供照片工具且查證預填不可用；已撤桶阻擋工具；未知命令凍結輸入並保留原 body／key／ETag。模擬照片仍按用途隔離，原照片入口維持。

## 驗證

沿用已確認的 Playwright 使用者畫面＋HTTP 攔截邊界。新增測試包含：

1. 屬實／不實預填不送出，明確確認才提交原查證 API；未知結果凍結輸入並重試原資料。
2. 完成照／現況照皆為可解碼 PNG，預覽、原因預填不寫入；明確上傳各走正確 purpose，互不清除另一份草稿，沒有自動 finish／dismiss／defer-repair。
3. 未到場、非本人、撤桶時不能透過模擬工具繞過限制。
4. 桌面及手機各執行，手機照片區另以 320px 檢查無橫向溢出；已檢視畫面截圖。

僅本機 build 與 API 攔截測試，未在雲端查證、上傳照片、發點、停權或結案；未驗證真實相機、GPS、實體手機及後端整合。Vite 大型 bundle 警告仍存在。預填後的實際送出會寫入目前連接的後端，不是純本機帳本。

## 執行結果

- `npm run typecheck`（由 build 執行）、`npm run data:check`、`npm run build` 通過。
- 新增工單模擬工具桌面／手機共 10 項通過；與市民模擬輸入的共用 PNG 回歸亦通過。
- 完整 `npm run test:e2e` 通過 348 項（7.1 分鐘），包含原照片上傳、ETag 衝突、身份失效及原命令重試、滿桶／非滿桶／修繕／無需處理與舊展示流程。測試透過臨時設定重用 5174 dev server，保留 5173 production preview。
- 已檢視桌面查證與 320px 手機照片工具截圖；未對雲端執行任何查證或掛照操作。
